# Use Daytona for sandbox compute

V1 uses Daytona container Sandboxes, controlled directly from the Cloudflare/Flue conversation owner through the provider-neutral Sandbox Adapter. Daytona was selected over Modal because Modal's JavaScript SDK needs a Node gRPC bridge outside the Durable Object, while Daytona supports direct Cloudflare-runtime control and preserves a container's filesystem across stop/start. RAM and processes are intentionally disposable: Flue owns logical continuation and the Working Branch plus Git Code Checkpoints remain recovery truth. Linux VM pause/resume was removed from the decision after Daytona reported no `linux-vm` runners in the selected region and the design review established that memory continuity was an optimization, not a requirement. Production use with private repositories requires a deterministic fail-closed Daytona egress policy at an acceptable tier or organization policy, plus validation that container isolation meets the threat model.
